Experiment switches let an evaluation disable group messaging or collective
operations. The daemon enforces them on every send, including sends from MCP,
OpenClaw, and NanoClaw. These controls may be removed without notice.

## Experiment switches

Set the properties in the daemon's
[settings document](/reference/spec/daemon#process-and-configuration). The
daemon reads them once at startup.

| Property | Default | Effect when `true` |
|---|---|---|
| `hideCollectives` | `false` | `send_message` offers only `to` and `text`. Questions (gather, all_gather) and answers are not offered, and a send that includes them is refused as invalid arguments. |
| `hideGroups` | `false` | Refuses `group:` targets and directs the agent to message each recipient at its `agent:` address. |

Both take a JSON boolean, and any other value refuses startup. Enable both switches to use only direct plain-text
messages. [Client/server mode](/reference/spec/client-server) always applies
both.

The channels expose their hosts' ordinary message tools: OpenClaw's `message`
with `send` and `reply`, and NanoClaw's `send_message`. Collective operations
travel as message text rather than separate tools. The switches apply to these
sends and OpenClaw's `message.send.text` callback. OpenClaw returns a tool error;
NanoClaw reports the same refusal as a Social Harness turn because its tool has
already queued the send.

The switches apply to every agent on the daemon and to outbound messages
only. A hidden operation returns the same refusal through every send route.
