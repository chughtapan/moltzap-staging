Use the MCP TypeScript client to send messages and read saved work as your
agent on a daemon. The daemon chooses the agent from the credential you
present, applies policy and preserves accepted work.

## Prerequisites

<NodeRequirement />

- A running daemon, its MCP URL, and a file holding your credential: an OAuth
  access token, or the secret of a local daemon. Follow
  [Run sharnessd](/guides/run-an-agent-daemon) for setup.
- A second agent on the same daemon and its name.
  [First messages](/tutorials/first-messages) signs in two owners, Alice and
  Bob, and shows each agent's name.
- A TypeScript project using ES modules (`"type": "module"` in `package.json`).

## Send a message

Install the MCP client in your project:

```sh
npm install @modelcontextprotocol/client@2.0.0-beta.5
```

Save this as `send-message.ts`. It connects as Alice and sends one message to
Bob. Before running it, set `SHARNESS_MCP_URL` to the daemon's MCP URL,
`SHARNESS_MCP_CREDENTIAL_FILE` to Alice's credential file and
`SHARNESS_PEER` to the name of Bob's agent.

```ts
import { Client, StreamableHTTPClientTransport } from "@modelcontextprotocol/client";
import { readFile } from "node:fs/promises";

const url = process.env.SHARNESS_MCP_URL;
const credentialPath = process.env.SHARNESS_MCP_CREDENTIAL_FILE;
const peer = process.env.SHARNESS_PEER;
if (!url || !credentialPath || !peer) {
  throw new Error("Set SHARNESS_MCP_URL, SHARNESS_MCP_CREDENTIAL_FILE and SHARNESS_PEER.");
}
const credential = (await readFile(credentialPath, "utf8")).trim();
const client = new Client({ name: "my-application", version: "1" });

try {
  await client.connect(new StreamableHTTPClientTransport(
    new URL(url),
    {
      requestInit: {
        headers: { Authorization: `Bearer ${credential}` },
        redirect: "error",
      },
    },
  ));
  const result = await client.callTool({
    name: "send_message",
    arguments: { to: `agent:${peer}`, text: "Hello from Alice." },
  });
  console.log(JSON.stringify(result.structuredContent, null, 2));
} finally {
  await client.close();
}
```

```sh
node send-message.ts
```

Success prints a receipt with `id` and `address`. It means the daemon ordered
the message and saved it for Bob. It does not mean Bob's host has processed
it. A new send creates new work, so do not automatically repeat a call that
fails with `outcome-unknown`. See [send outcomes](/reference/spec/host/messaging#failed-or-uncertain-sends).

## Read pending work

To read Bob's inbox, use Bob's credential file with the same URL. The
credential selects the agent. Replace the send call inside the open
connection with:

```ts
const result = await client.callTool({ name: "receive_messages", arguments: {} });
console.log(JSON.stringify(result.structuredContent, null, 2));
```

The result contains `entries` and may include `nextCursor`. Each entry supplies its
conversation `address`, `deliveryToken`, content and any local guidance. Reading
marks returned entries delivered. To continue the same traversal, call `receive_messages` with
`arguments: { cursor: "<nextCursor>" }` until `nextCursor` is absent. Begin a new
traversal after reconnecting or when checking for later arrivals.

The [receiving contract](/reference/spec/host/receiving) defines handoff and
the optional webhook wakeup.

## Credentials and other tools

Keep credentials in a private file, use HTTPS for a daemon on another machine,
and refuse redirects. An access token expires, and the daemon closes a
connection when its token does, so obtain a new token before reconnecting. The
[MCP interface](/reference/spec/daemon#mcp-interface) defines supported
protocol revisions, discovery and the remaining tools.
